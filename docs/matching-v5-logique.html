1) Objectif et périmètre

Le Matching V5 part du cadastre pour produire des entités exploitées en prospection (principalement des lignes de grain parcelle), enrichies avec bâtiment(s), SIREN/SIRET, adresses et signaux métier.

Finalité produit: identifier des parcelles à potentiel solaire et qualifier les opportunités via les données cadastrales, bâtiments, entreprises et points d’intérêt.

Références code principales: data-pipeline/matching_v5/run_matching_v5.py, lib/scout-matching-v5-map.ts, app/api/matching-v5/features/route.ts.

2) Sources de données

Cadastre

cadastre_france_feuilles_geom

  • Clés: code_insee, section, numero_norm
  • Géométrie parcelle en EPSG:4326
  • Base de référence pour le scout_v5_id

Passerelle PPM

parcelles_personnes_morales

  • Lien parcelle ↔ SIREN
  • Adresse passerelle (numéro/voie/commune)
  • Source du siren_status

Bâtiments

Empreintes OSM + enrichissement BDNB

  • Empreinte géométrique prioritaire: osm_building_footprints
  • Building ID unitaire: batiment_construction_id
  • Enrichissement BDNB/FFO (intersection, année, attributs)
  • Jointure spatiale avec parcelles
  • Agrégats footprint_sum_m2, règles partage

Établissements / POI

scout_etablissements, osm_poi, fallback Google optionnel

  • Matching d’adresse vers SIRET/SIREN
  • Qualification activité / contexte
  • Signal business complémentaire

3) Pipeline logique pas à pas

1. Charger les parcelles cadastrales (code_insee ciblé)
2. Associer les bâtiments (empreintes OSM, puis enrichissement BDNB)
3. Calculer intersections parcelle ↔ bâtiment (aire en m²)
4. Résoudre les cas multi-parcelles (matching_status=partage)
5. Appliquer les filtres de surface (et éventuelles dérogations landuse)
6. Construire l’adresse passerelle (PPM) + adresses candidates
7. Matcher vers établissements (score voie/numéro/indice/fuzzy)
8. Déterminer les statuts (technique + métier + confiance)
9. Enrichir avec POI OSM / fallback Google (optionnel)
10. Exporter en CSV/GeoJSON puis upsert Postgres (scout_matching_v5_features)

4) Règles métier clés

4.1 Résolution des bâtiments partagés

  • Si un batiment_construction_id intersecte plusieurs parcelles: matching_status=partage.
  • Si des SIREN communs existent entre parcelles concernées, sélection d’un SIREN gagnant (majorité de lignes PPM), puis parcelle gagnante par plus grande aire d’intersection.
  • Sans SIREN commun: affectation directe à la parcelle avec l’aire d’intersection maximale.

4.2 Filtrage surface

  • Seuil principal parcelle: footprint_sum_m2 >= min-parcelle-footprint-sum-m2 (souvent 400 m²).
  • Seuil bâtiment d’entrée: min-batiment-footprint-m2.
  • Dérogation possible pour certains landuse économiques (commercial/industrial/retail), selon pipeline.

4.3 Cascade d’adresse d’affichage (display_address)

  1. Adresse OSM footprint (addr:*)
  2. Adresse PPM corroborée
  3. Reverse geocoding Géoplateforme (seuils stricts)
  4. Adresse établissement SIRENE proche

Si non confirmée, la confiance vaut none (adresse non affichée comme fiable).

6) Extension cadastre_only

6.1 Pourquoi

Permettre d’afficher et manipuler des parcelles présentes au cadastre mais absentes du flux “matched” (utile en mode édition/élargissement de périmètre).

6.2 Implémentation SQL

Migration dédiée:

ALTER TABLE public.scout_matching_v5_features
ADD COLUMN IF NOT EXISTS match_status TEXT NOT NULL DEFAULT 'matched';

CHECK (match_status IN ('matched', 'cadastre_only'));
INDEX match_status;

6.3 Règle de non-régression

Lors d’un upsert cadastre_only, une ligne déjà matched ne doit jamais être rétrogradée. 

CASE
  WHEN existing.match_status = 'matched' THEN 'matched'
  ELSE 'cadastre_only'
END

6.4 Scope de déploiement actuel

Activation limitée au code INSEE 33318 (Pessac) via garde-fou applicatif isCadastreOnlyUpsertEnabledForCodeInsee.

7) APIs et consommation front

GET /api/matching-v5/features

  • Filtres: scout_v5_id, code_insee, ou bbox (minLat/maxLat/minLng/maxLng).
  • mode=overview: renvoie des géométries en PointOnSurface pour performance carte.
  • Mode détail: géométrie polygonale + building_geometries_json.

GET /api/matching-v5/parcelles-adjacent

  • Modes: anchor, bbox, lookup.
  • Source cadastre directe, puis upsert éventuel en cadastre_only.
  • Retourne aussi in_matching_v5 et match_status.

8) Sorties et persistance

  • CSV pipeline: data-pipeline/out/matching/v5/matching_v5.csv.
  • GeoJSON statique: public/geo/matching-v5-33318.geojson.
  • Table applicative: public.scout_matching_v5_features (source API + UI Discovery).
  • Combos overview: public.scout_matching_v5_combos pour agrégats multi-parcelles.

9) Cas limites et garde-fous

  • Parcelles sans PPM: pas d’adresse passerelle exploitable, matching entreprise limité.
  • Adresse ambiguë: maintien d’un status_technique conservateur.
  • Idempotence SQL: migration et upserts pensés pour rejouabilité.
  • Protection métier: matched prioritaire sur cadastre_only.
  • Performance carte: bbox capée, mode overview en points, limite de résultats.
